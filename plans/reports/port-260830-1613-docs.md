the installer's managed block. `rg 'ariadnev:start|managed block' kit/` found
nothing — the 1.4.0 skill never mentioned it. The markers are

## Dropped, and why

- **`llms-full.txt` generation and script delegation** (upstream `llms.md`
  sections 5-6, and "both files" wording throughout). ariadnev's 1.4.0
  Workflow position records a deliberate boundary — `av:llms` owns the general
  generator (arbitrary paths/URLs, custom output, inline `llms-full.txt`) and
  `/av:docs llms` covers only a links-only index from `docs/` — set in the Tier A
  authoring pass (`57a2e38`). Porting the widening would silently reverse that
  decision, so the new `llms.md` keeps the narrow scope and hands the wider
  cases to `/av:llms` explicitly. Upstream's path
  `../ak-llms/scripts/generate-llms-txt.py` was not ported for the same reason
  (the ariadnev counterpart exists at `kit/skills/llms/scripts/generate-llms-txt.py`
  if the coordinator decides otherwise).
- **Upstream's generic diagram sentence** ("use the installed diagram skill").
  ariadnev's wording names `av:mermaidjs-v11` / `av:tech-graph`; kept.
- **`metadata.author: agentkit`** — ariadnev uses `origin: ported` /
  `author: upstream`; kept, version bumped to `1.9.0`.
