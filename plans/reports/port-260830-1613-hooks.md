## Unresolved questions

1. The commit omits the `Claude-Session:` trailer the harness suggests, because the user's development rules require conventional commits without AI references. Re-add if the coordinator prefers the trailer.
2. `kit-embedded.generated.ts` was not touched. `build:binary` regenerates it from the kit tree, so the release picks up `shell-command-segments.cjs` automatically — but any check that compares the in-tree generated file against the kit tree will be stale until someone runs `pnpm --filter cli generate:embedded`.
3. Existing installs: `ariadnev doctor` now reports the missing marker with remedy `ariadnev install`. I did not verify whether `ariadnev update` re-plans an install (and therefore writes the marker) or only swaps the binary.
4. The doctor validity check reads the marker as text and parses it; the hook lib additionally rejects symlinks and files over 4096 bytes. Doctor does not replicate those two rejections.
5. The marker names `r.id`. If a provider other than claude-code ever passes `isVerified(id, "hook")`, its id must also be in the hook lib's `SUPPORTED_RUNTIMES` (claude-code, codex) or the hooks will reject the marker the installer wrote.
